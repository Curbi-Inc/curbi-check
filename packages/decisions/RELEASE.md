# Release handoff: `@curbi/decisions` (npm) and `curbi-decisions` (PyPI), 0.1.0

Prepared by CAIO; published by the release owner (CTO). Nothing here is published yet, and committing this creates no publisher identity or token. The general trust and bootstrap steps are in [`../PUBLISHING.md`](../PUBLISHING.md). That file is exported from curbi-platform and pinned by digest, so these two rows belong in its source table there:

| Registry | Package | GitHub owner / repository | Workflow filename | Environment |
|---|---|---|---|---|
| npm | `@curbi/decisions` | `Curbi-Inc` / `curbi-check` | `publish-npm-decisions.yml` | `npm` |
| PyPI | `curbi-decisions` | `Curbi-Inc` / `curbi-check` | `publish-python.yml` (project `curbi-decisions`) | `pypi` |

## What ships
- **`@curbi/decisions`:** `adapters/decisions/src/decisions.mjs`, byte for byte (`packages/decisions/test/package.test.mjs` fails if it drifts), plus `index.d.ts`, README, LICENSE and CHANGELOG. No runtime dependencies. Node 22 or later.
- **`curbi-decisions`:** a Python port of the same adapter. No dependencies. Python 3.10 or later. It must reproduce every vector in `packages/decisions-py/tests/vectors.json`: records, routes, receipts, action findings, digests and error messages. The vectors are generated by `make_vectors.mjs` from the JavaScript adapter, and a JavaScript test fails if they're stale.
- **Version:** 0.1.0 everywhere. `scripts/check-packages.py` also requires the adapter's `CHECKER` string to match both package versions.

## Steps
1. Merge the branch to `main`. CI (`framework-packages`) runs the adapter and package tests, packs the npm tarball and imports it as a clean consumer, and builds the Python wheel and sdist, runs `twine check`, then tests the installed wheel.
2. **npm:**
   - Bootstrap `@curbi/decisions` through the account's supported first-publish flow, from the reviewed tarball.
   - Then add the trust tuple above in package settings.
   - Dispatch `publish-npm-decisions.yml` from `main` with version `0.1.0` and the confirmation box checked.
3. **PyPI:**
   - After the earlier projects have bootstrapped, add a `curbi-decisions` pending publisher with the tuple above.
   - Dispatch `publish-python.yml` with project `curbi-decisions`, version `0.1.0` and confirmation.
4. **Verify:** install each from the registry into a fresh environment and rerun its tests.

## Local evidence (CAIO, this branch)
- `npm pack ./packages/decisions`: 6 files, 12.1 kB. A clean consumer imported `@curbi/decisions` from `node_modules`.
- `python -m build packages/decisions-py`: wheel and sdist pass `twine check`. The installed wheel, imported from `site-packages`, passes 1,797 tests: 1,790 parity vectors plus 7 native tests.
- Artifact digests are in the #43 post for this branch. Rebuilds after any change will differ.

## Limits
- Receipts are unsigned (`signed: false`, `provider_signed: false`).
- Vendor field names are as recorded in `adapters/decisions/FIELDS.md`. Microsoft-Decision-1 isn't modeled.
- Raw-byte binding shows what the host received, not that the vendor sent it.
